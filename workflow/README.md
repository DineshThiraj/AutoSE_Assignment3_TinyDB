# Controller implementation and validation

This implementation follows the initial design commit `67c9b3c4286f598d5d415fb60433870cf63035a8`. It has not been executed on GitHub. The optional API adapter has only mocked-transport tests. Live model support, billing controls and secrets remain unresolved.

`autose/common.py` owns budgets, fixed stage names, hashed immutable artifacts and MERGE_READINESS_CHECK. `contracts.py` checks A1 outputs/criteria, design grounding and reviewer findings. `source.py` reads the genuine pinned Git tree and admits only regular TinyDB file replacements or new `tests/test_autose_*.py` tests. `engine.py` controls gates/routing; `cli.py` executes one trusted phase per job. `github.py` performs allowlisted GitHub API publication without running target code. `broker.py` constructs fresh role contexts and optionally uses the Responses protocol after explicit setup.

The static Actions graph contains 41 possible jobs: two review cycles, at most two implementation/test attempts in each, plus admission, preparation, selection/publication/review/finalization jobs. Many jobs are skipped on a successful or blocked run. Requirements/design are rerun only when the validated review route requires them; every downstream gate is invalidated. Four reasoning roles include one shared implementation/test-author role using separate requests. There is no model planner or recursive workflow trigger.

Only `autose-broker.yml` receives AUTOSE_MODEL_API_KEY. Execution/data jobs have read permissions; `autose-publish.yml` has fork-scoped contents/PR write and Actions read. All checkouts disable persisted credentials. Containers receive only source and an output mount, no Git metadata or Actions/provider credentials. The CI workflow runs controller/Dockerfile code from the base SHA and reads the exact PR head as inert candidate files. The target environment uses Python 3.12, pinned pytest 9.2.0 and a recorded image ID; OS/base-image reproducibility remains a limitation until a hosted image digest is frozen.

Hosted execution disables network, drops capabilities, disallows privilege escalation, uses read-only root/source, limits CPU/memory/PIDs/file sizes and imposes a five-minute subprocess timeout. Timeout cleanup removes the named container. Docker daemon access is denied in the current coordinator environment; the container path remains unverified. The local_fixture option is for coordinator-authored fixtures only, is explicitly unsandboxed, strips the environment, and is rejected on GitHub Actions. Never use it for live generated code.

Artifact manifests cover all flat files and state; per-run/attempt names prevent overwrite. Trusted discovery reads only artifacts from the current workflow run, chooses the latest checkpoint per logical phase and ignores expired/future attempts/prior finalizers. Every stage writes failure evidence and blocks downstream progression. Hard runner termination can still lose the active artifact, leaving previous checkpoints. Artifacts request 90-day retention; essential actual hosted evidence must later be exported into results for grading.

A stable `autose/issue-N` branch and its PR form the durable issue-to-PR index. Admission refuses an existing issue PR before spending; unfamiliar existing branches stop for reconciliation. Publication reuses a matching tree/PR after interruption and uses ordinary non-forced ref updates for repairs. Rerunning failed release/review jobs can recover prior current-run artifacts. Rerunning the entire issue admission after publication deliberately stops; it does not create another PR or silently replay paid work. An authorized clarification requires editing the issue and an authorized fresh trigger while no active issue PR exists.

Default ceilings are 24 broker calls, 40 minutes of elapsed run time, two total review rounds, two implementation/test attempts per round, five-minute test process and 15-minute API timeout. Token/output ceilings and paid amount require verified provider pricing/approval. Calls are counted before transport; uncertain usage stops further calls, known usage is retained even for incomplete responses. No automatic HTTP retry, model fallback or provider substitution occurs. External cap enforcement is a provisioning prerequisite, not a property created by local flags.

Original tests are immutable and their 228 JUnit IDs are independently checked. Every AC must map to a newly authored asserted test that actually collects. Structural and LLM semantic gates remain imperfect: generated Python can monkeypatch runtime behavior, an assertion can be weak, tests cannot prove absence of malicious semantics, and a model can miss unsupported scope or defects. Hidden tests and seeded ground truth remain outside agent context. Five seeded cases and both decision experiments are not yet run.

Release polls for up to five minutes for successful `autose-ci.yml` PR CI at the exact released head, verifies job conclusions, and saves pending when approval/no-run prevents progress. Publication never treats missing/skipped/stale CI as success. The GitHub identity may reject approving its own PR; in that case the publisher posts a clearly labelled COMMENT and the review gate stays pending. Two exhausted review rounds terminate unapproved. Only a person makes a final merge/close decision.

All generated workflow files are mirrored in workflow/workflows. Regenerate the AutoSE files using `python workflow/generate_workflows.py` with PyYAML installed; controller runtime otherwise uses Python standard library. The generator and structural tests are not a replacement for actionlint or actual hosted validation; actionlint is unavailable here.

The inherited upstream push/PR CI and tag-based PyPI publisher are replaced by inert manual notices in this fork. Their original bytes remain at the pinned commit and workflow/upstream-reference. This prevents a parallel legacy runner from executing generated code with persisted checkout or publishing credentials. Only the isolated AutoSE CI handles generated issue PRs.
