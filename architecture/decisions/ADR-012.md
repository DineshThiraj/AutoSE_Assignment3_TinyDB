# ADR-012 · One-use provider authorization

## Status

Retrospective implementation record, 20 November 2026. Student review pending. Refines [ADR-009](ADR-009.md). The original ADR retains its decision and chronology.

## Context

A read-only grant check did not atomically consume authorization for an individual paid call. A local concurrent test observed three provider-double calls using one allowed slot.

## Decision

Reserve numerical spending bounds and consume each slot atomically before provider HTTP. Bind the receipt to the grant, request, run, job and fresh invocation. Keep the consumer’s GitHub write token separate from model credentials. Fail closed and retain the reservation when the response is uncertain.

## Consequences

Three concurrent attempts on one slot reached the fake provider only once in a local test. The design adds a protected external service and ledger dependencies. Hosted atomicity, actual billing and hard-cap configuration remain unverified. See [experiment E2](../../experiment/variants.md).
