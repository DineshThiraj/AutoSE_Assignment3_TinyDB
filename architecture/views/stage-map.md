# Reviewed initial stage contracts — implementation evidence pending

Trusted controller is the final transition authority. All model content is evidence/proposal, never an executable command. Each saved stage artifact includes input hashes, base/head SHA, model/config, status, evidence and failure reason. No stage is marked passed by prose alone.

| Stage / agent | Input and permitted tools | Processing | Output | Gate | Failure / return |
| --- | --- | --- | --- | --- | --- |
| 1 Requirements role | Frozen authorized issue; actual A1 skill; bounded source reads | Extract provenance, scope, atomic requirements and measurable ACs; preserve unknowns and exact-scope authorization | spec.md plus original three A1 documents and AC metadata | Required AC fields complete, semantically testable, no unresolved critical ambiguity; A1 readiness satisfied | Save draft and clarification questions; stop needs_clarification; resume only with authorized clarification; reviewer may route here |
| 2 Design role | Validated spec, bounded source and actual A2 architecture | Inspect real definitions and map each criterion to files/functions and constraints | design.md and file/function metadata | Paths/functions exist or are explicitly new; every AC addressed; constraints checked | Stop with missing mappings; reviewer approach finding returns here |
| 3 Implementer | Approved design/spec; bounded code reads; allowlisted edit proposals | Propose real patch on unique branch; isolated worker applies it | diff.patch, compile log and head SHA | Patch policy passes; fixed compile command succeeds | Record apply/build error; bounded repair or stop |
| 4 Implementer test author + isolated executor | ACs, design, current source; permitted tests/ edits | Add test per AC, run full original and new suite with fixed command | test_report.md, AC-to-test map, logs, JUnit | All expected cases collected and pass; each AC has meaningful asserted test | Return to implementation within attempt/time budget; else stop |
| 5 Trusted release controller | Validated patch and exact SHA/test evidence; fork-scoped API publisher | Push unique branch, open/reconcile PR, obtain real CI at head SHA | pr.md, PR link, CI links | PR open, target/owner/base/head match, required CI success | Failed CI stops; approval-required CI records pending and correct human action, never success |
| 6 Independent reviewer + trusted review publisher | Issue, diff, latest sanitized PR checkout only; bounded reads and fixed no-secret test requests | Fresh-context findings with locations, verdict and affected-stage routing; post real review | review.md and review URL at head SHA | Reviewer approves OR two total review rounds consumed | Requests route to needed stage then all downstream gates; exhausted rounds ends unapproved, awaiting human decision |

After terminal state the workflow never merges. MERGE_READINESS_CHECK is proposed to list source/head match, six gate outcomes, original/new/hidden tests (hidden unavailable before external evaluation), CI head SHA, unresolved findings, review-round exhaustion, secrets scan and human decision = pending. A missing signal means unknown/pending, not ready.
